## 5. Worth knowing

**Behaviour changes on global** (all deliberate, all in their PRs):
- A GET that writes and is not in `GET_WRITERS` is **logged, not refused**, at home (refusing would
  turn an untested path into an outage). `reads-that-write.flow.test.ts` walks every GET route and
  fails on one; it found the OAuth callback, now listed.
- Nightly bundles no longer contain `BackgroundTask` rows (7-day job records, never org data).
- `scripts/backfill-movement-reference.ts` now **requires `--org`**. It used to read an
  `organizations` collection that does not exist (the model's is `orgs`), so `--org` always failed
  and a run without it touched every org.
- A script given an org homed elsewhere exits with code 2 before writing anything.
- `migrations` depends on `services` now (#177): run `bun install` after pulling.

**Traps found on the way:**
- **Stacked PRs:** retarget the next PR to `master` *before* deleting its base branch. Deleting the
  base first closes the stacked PR (it happened to #161; reopened and merged).
- **Bun `AsyncLocalStorage`:** a store entered after an `await` in an Elysia hook is not seen by the
  handler, and one entered synchronously leaks into later code in the same context, so it is reset
  after the response (#169, #172).
- **Bun on Windows** cannot hand a child process extra stdio pipes, so Puppeteer's `pipe: true`
  hangs there (it works on Linux and in the image).
- **Never `.rejects` / `.resolves`** in the test suite: on Windows one is enough to deadlock the
  whole run (Known Issues in `CLAUDE.md`).
